# Бриф проекта: MediaTracker (Менеджер личной коллекции)

## 1. Общие сведения

* **Название продукта:** MediaTracker — персональный каталогизатор и трекер личной коллекции.
* **Краткое описание:** Локальное десктопное приложение для систематизации медиаколлекции (игры, книги или фильмы), учёта статусов прохождения/просмотра и детальной аналитики. Программа решает проблему разрозненного хранения списков контента, помогает контролировать бэклог («В планах», «В процессе», «Завершено») и анализирует персональные предпочтения пользователя по жанрам и авторам.
* **Целевая аудитория:** Пользователи, желающие упорядочить собственную коллекцию контента, отслеживать личный прогресс, выставлять оценки и видеть наглядную статистику без зависимости от сторонних онлайн-сервисов.

---

## 2. Функциональные требования

### Обязательные требования (MVP):
1. **Пользователь может добавлять элементы коллекции** с указанием названия, года релиза, оценки (от 1 до 10), текстовой заметки и статуса.
2. **Пользователь может связывать элемент коллекции с несколькими жанрами и авторами/студиями одновременно** (связь многие-ко-многим).
3. **Пользователь может редактировать и удалять** существующие карточки элементов, а также записи в справочниках жанров и авторов.
4. **Пользователь может изменять статус прохождения** через фиксированный список («В планах», «В процессе», «Завершено», «Брошено»).
5. **Пользователь может выполнять поиск** по названию элемента (с поддержкой частичного ввода).
6. **Пользователь может фильтровать коллекцию** по статусу, выбранному жанру или конкретному автору.
7. **Пользователь может сортировать записи** по дате добавления, названию (алфавиту), году выпуска и оценке.
8. **Пользователь может просматривать сводную аналитику:**
   * Общее число элементов в базе;
   * Средняя пользовательская оценка по всей коллекции;
   * Топ-5 наиболее популярных жанров;
   * Топ-5 самых частых авторов/студий;
   * Распределение элементов по статусам (в штуках и процентах).

### Дополнительные требования:
1. **Пользователь может экспортировать** отфильтрованную таблицу или статистику в файл формата CSV.
2. **Пользователь может прикреплять путь к локальному изображению постера/обложки** для отображения в карточке.
3. **Пользователь может вести учёт времени** (добавление поля «Затрачено часов» и подсчёт общего времени в аналитике).

## 3. Нефункциональные требования

* **Язык интерфейса:** Русский.
* **Тип приложения:** Локальное десктопное приложение (Desktop GUI).
* **Производительность:** Время отклика интерфейса при поиске, сортировке и фильтрации — не более 1 секунды при объёме базы до 5 000 записей.
* **Хранение данных:** Локальная реляционная база данных SQLite (хранение в одном файле `.db`), приложение работает полностью автономно без сети.
* **Защита от ошибок и валидация:**
  * Запрещено сохранять запись с пустым полем названия.
  * Оценка строго валидируется диапазоном целых чисел от 1 до 10 (либо остаётся пустой).
  * Год выпуска ограничен корректным диапазоном (например, от 1950 до текущего года + 2).
  * Запрещено удалять статус, если к нему привязаны элементы в базе (`ON DELETE RESTRICT`).
  * При удалении элемента коллекции все связанные записи в промежуточных таблицах `item_genres` и `item_authors` удаляются автоматически (каскадно).
* **Инициализация БД:** При первом запуске приложение автоматически создаёт файл базы данных и накатывает структуру таблиц вместе с начальным набором статусов.

## 4. Модель данных (ER-диаграмма)

### Структура таблиц базы данных

1. **`statuses` (Справочник статусов)**
   * `id` — INTEGER, Primary Key, Autoincrement
   * `name` — TEXT, NOT NULL, UNIQUE (значения: «В планах», «В процессе», «Завершено», «Брошено»)

2. **`genres` (Справочник жанров)**
   * `id` — INTEGER, Primary Key, Autoincrement
   * `name` — TEXT, NOT NULL, UNIQUE

3. **`authors` (Справочник авторов / разработчиков / режиссеров)**
   * `id` — INTEGER, Primary Key, Autoincrement
   * `name` — TEXT, NOT NULL, UNIQUE

4. **`items` (Элементы коллекции)**
   * `id` — INTEGER, Primary Key, Autoincrement
   * `title` — TEXT, NOT NULL
   * `release_year` — INTEGER
   * `user_rating` — INTEGER (от 1 до 10, NULLABLE)
   * `review_note` — TEXT
   * `status_id` — INTEGER, NOT NULL, Foreign Key -> `statuses(id)`
   * `created_at` — DATETIME, DEFAULT CURRENT_TIMESTAMP

5. **`item_genres` (Связующая таблица M:N)**
   * `item_id` — INTEGER, NOT NULL, Foreign Key -> `items(id)` ON DELETE CASCADE
   * `genre_id` — INTEGER, NOT NULL, Foreign Key -> `genres(id)` ON DELETE CASCADE
   * *PRIMARY KEY (`item_id`, `genre_id`)*

6. **`item_authors` (Связующая таблица M:N)**
   * `item_id` — INTEGER, NOT NULL, Foreign Key -> `items(id)` ON DELETE CASCADE
   * `author_id` — INTEGER, NOT NULL, Foreign Key -> `authors(id)` ON DELETE CASCADE
   * *PRIMARY KEY (`item_id`, `author_id`)*

### Обоснование нормализации
Схема спроектирована в **3-й нормальной форме (3НФ)**:
* Все атрибуты атомарны.
* Жанры и авторы вынесены в независимые справочники, что исключает дублирование названий строк в таблице `items`.
* Реализованы таблицы связей `item_genres` и `item_authors` с составными ключами, что исключает дубликаты и реализует отношение многие-ко-многим (M:N).

## 5. Макеты интерфейса

Приложение содержит 3 ключевых экрана:

### Экран 1: Главное окно (Каталог)
* **Верхняя строка:** поиск по названию; фильтры по жанру и статусу; переключатель сортировки (по дате / по оценке).
* **Центральная часть:** таблица со списком элементов (Название, Год, Жанры, Авторы, Статус, Оценка).
* **Панель действий:** кнопки «Добавить запись», «Редактировать», «Удалить», «Аналитика».

### Экран 2: Форма добавления / редактирования
* Поля ввода: «Название» (обязательное), «Год выпуска».
* Выбор жанров и авторов через списки с флажками (чекбоксами) + кнопки быстрого добавления нового значения `[+]`.
* Выпадающий список выбора статуса («В планах», «В процессе», «Завершено»).
* Поле ввода оценки (от 1 до 10) и текстовое поле для заметок.
* Кнопки «Сохранить» и «Отмена».

### Экран 3: Панель аналитики
* Ключевые показатели: общее число записей в коллекции, средняя оценка.
* Диаграмма/список распределения элементов по статусам.
* Таблица «Топ-5 жанров» и «Топ-5 авторов/студий» с количеством элементов.
* Кнопка возврата в каталог.

## 6. Сценарии использования

### Сценарий 1. Добавление нового элемента
* **Актёр:** Пользователь
* **Предусловие:** Главное окно приложения открыто
* **Основной поток:**
1. Пользователь нажимает кнопку «Добавить запись».
2. Система открывает диалоговое окно формы.
3. Пользователь заполняет название, год, выбирает нужные жанры, автора, статус и выставляет оценку.
4. Пользователь нажимает кнопку «Сохранить».
5. Система проверяет данные, вносит запись в `items`, создаёт связи в промежуточных таблицах и обновляет общий список.
* **Альтернативный поток:** Поле «Название» оставлено пустым. Система подсвечивает поле красным цветом и выводит сообщение: «Название не может быть пустым».

---

### Сценарий 2. Поиск и фильтрация
* **Актёр:** Пользователь
* **Предусловие:** В базе уже сохранены элементы
* **Основной поток:**
1. Пользователь вводит текст в поисковую строку и выбирает фильтр по статусу «В планах».
2. Система фильтрует данные по условию `LIKE` и `status_id`.
3. Список обновляется, отображая только найденные совпадения.
* **Альтернативный поток:** Совпадений не найдено. Система очищает таблицу и выводит уведомление о том, что ничего не найдено.

---

### Сценарий 3. Открытие аналитики
* **Актёр:** Пользователь
* **Предусловие:** В коллекции есть сохранённые записи с оценками
* **Основной поток:**
1. Пользователь переходит в раздел аналитики по кнопке в интерфейсе.
2. Система выполняет агрегирующие SQL-запросы (`COUNT`, `AVG`, `GROUP BY`).
3. На экране отображаются готовые статистические карточки и распределение по статусам.
* **Альтернативный поток:** База данных пуста. Система показывает нули в счетчиках и сообщает о нехватке данных для расчёта.

---

## 7. Критерии приёмки

* База данных SQLite и структура всех таблиц создаются автоматически при первом запуске
* Реализовано добавление элемента с привязкой сразу к нескольким жанрам и авторам
* Главная таблица корректно выводит все сохранённые элементы и связанные данные
* Редактирование и удаление записей корректно обновляет данные в базе
* При удалении карточки автоматически очищаются промежуточные связующие таблицы
* Валидация блокирует сохранение без названия и ввод оценок вне диапазона от 1 до 10
* Регистронезависимый поиск по названию находит частичные совпадения
* Фильтры по жанрам и статусам корректно отбирают нужные записи
* Сортировка упорядочивает данные таблицы по возрастанию и убыванию
* Экран аналитики правильно рассчитывает средний балл и топ популярных жанров
* Приложение устойчиво к некорректным действиям пользователя и не вылетает при ошибках ввода
