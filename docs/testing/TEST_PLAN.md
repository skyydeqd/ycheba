# Тест-план проекта GameTracker

## 1. Объект тестирования
**GameTracker** — настольное приложение на языке Python с локальной базой данных SQLite для ведения персональной игровой коллекции, учёта статусов прохождения («В планах», «В процессе», «Завершено»), выставления оценок и просмотра статистики.

## 2. Цели тестирования
* Проверить корректность работы всех функций, заявленных в брифе (CRUD-операции, поиск, фильтрация, сортировка, статистика).
* Убедиться в корректности работы связей между таблицами БД (включая связи «многие-ко-многим» и каскадное удаление).
* Проверить устойчивость приложения к некорректному пользовательскому вводу и граничным значениям.
* Убедиться в корректной инициализации базы данных при первом запуске и сохранности данных между сеансами работы.
* Проверить удобство и отзывчивость графического интерфейса.

## 3. Области тестирования
* **Функциональное тестирование:** добавление, редактирование, удаление игр, добавление новых жанров и разработчиков, поиск по названию, фильтрация по жанру и статусу, сортировка списка, расчёт показателей статистики.
* **Тестирование интерфейса (UI):** корректное отображение таблиц, списков выбора, модальных окон, кнопок и всплывающих сообщений об ошибках.
* **Тестирование устойчивости к ошибкам:** ввод пустых строк, пробелов, текста вместо числового года, оценок вне диапазона 1–10, попытка сохранения карточки без жанра.
* **Тестирование целостности данных:** проверка работы ограничений БД (`CHECK`, `FOREIGN KEY`, `ON DELETE CASCADE`, `ON DELETE RESTRICT`), автоматическое создание файла `game_tracker.db` при первом запуске и сохранение изменений после перезапуска программы.
* **Тестирование производительности:** время отклика при поиске, фильтрации и переключении окон не должно превышать 1 секунды.

## 4. Уровни критичности дефектов
* **Критический (Critical):** приложение аварийно завершается (падает), теряются сохранённые данные, база данных не создаётся при первом запуске, основная функция полностью не работает.
* **Значительный (Major):** функция работает с ошибками (например, неверно считается средняя оценка или не срабатывает фильтр), но приложение не падает.
* **Незначительный (Minor):** мелкие визуальные недочёты интерфейса (обрезанный текст, опечатка в уведомлении), не мешающие работе.
* **Рекомендация (Enhancement):** предложение по улучшению удобства интерфейса, не являющееся ошибкой.

## 5. Критерии начала тестирования
* Реализованы и связаны все слои приложения: БД (`init.sql`, `database.py`), слой доступа к данным (`dao.py`), бизнес-логика (`services/`) и графический интерфейс (`app.py`).
* Модульные и консольные тесты (`main.py`, `test_logic.py`) проходят без ошибок.

## 6. Критерии завершения тестирования
* Выполнены все тест-кейсы из документа `TEST_CASES.md`.
* Устранены все дефекты уровней «Критический» и «Значительный».
* Оформлен итоговый отчёт о тестировании (`TEST_REPORT.md`).

## 7. Требования к тестовым данным
* Перед началом основного функционального тестирования в базе данных должны присутствовать минимум 3–5 тестовых игр с разными статусами («В планах», «В процессе», «Завершено»), разными годами выпуска, оценками (включая отсутствие оценки) и привязкой к нескольким жанрам и разработчикам.
* Для проверки инициализации первого запуска используется чистая директория без файла `game_tracker.db`.
